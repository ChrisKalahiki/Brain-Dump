# Brain-Dump v1 spec

Brain-Dump gets the things worked out in AI Sessions into the Vault before they are lost. In v1 it is two agent skills plus one saved prompt:

- **`dump`**: run inside a Session; writes one Dump into the Vault's `Inbox/`.
- **`file`**: run on demand; proposes a Filing Plan for each unfiled Dump and, once approved, appends the Items to Weekly Notes, Topic Notes and Project Notes.
- **Chat prompt**: makes a chat app (Claude web, ChatGPT, Gemini) write a Dump body for `dump --paste`.

Terms are defined in [`GLOSSARY.md`](../../GLOSSARY.md). The form factor is recorded in [ADR 0001](../adr/0001-agent-native-commands.md). Every decision below links to the ticket that holds its detail on the [Brain-Dump v1 map](https://github.com/ChrisKalahiki/Brain-Dump/issues/1).

## Scope

**In:** dev Sessions in Claude Code and Codex CLI; chat-app Sessions through the chat prompt; one Vault at `~/Documents/The Vault` (Obsidian Sync); Linux and macOS; a single user.

**Out (v1):**
- Windows and mobile.
- A second Vault.
- Fully automatic Filing.
- Rewriting or removing existing note content.
- `file` in Codex.
- A remote MCP `dump` tool, and Claude Desktop folder writes.
- Link and paper enrichment.

## 1. The Dump file

Decided in [What does a Dump file look like?](https://github.com/ChrisKalahiki/Brain-Dump/issues/4) and [Which route captures a chat-app Session as a Dump?](https://github.com/ChrisKalahiki/Brain-Dump/issues/8).

- **Location:** `<Vault>/Inbox/`, one file per Dump.
- **Filename:** `YYYY-MM-DD HHmm <project> - <slug>.md`.
  - `<project>` is the git repo name. Outside a repo it is the directory name. For a chat Session it is the tool tag.
  - `<slug>` is a short title the agent writes.
  - On a name collision, append `-2`, `-3` and so on.
- **Frontmatter:** tags only, as a block list:
  - `dump`
  - `AIGenerated`
  - exactly one tool tag: `ClaudeCode`, `Codex`, `ClaudeWeb`, `ChatGPT` or `Gemini`

  No topic tags; topic tagging is left to Filing.
- **Origin line:** the first body line.
  - **Dev Session:** `Session: <tool> · \`<repo path>\` @ \`<branch>\` · YYYY-MM-DD HH:mm · [[<project>]]`. Omit `@ <branch>` when there is no branch.
  - **Chat Session:** `Session: <tool> · <chat URL if known> · YYYY-MM-DD HH:mm`, plus ` · [[<project>]]` only when the user names a project.
  - The `[[<project>]]` link may be unresolved. Filing resolves it.
- **Body:** up to three sections, in this order, each omitted when empty:
  - `## Learnings`
  - `## Decisions`
  - `## Todos`
- **Items:**
  - Every Item is one checkbox line, `- [ ] <text>`.
  - A Decision carries an indented `\t- Why: <Rationale>` line.
  - Todos also carry `#todo`.
  - URLs found in the Session stay inline in the Item text.
- **Item states**, which `file` sets:
  - `- [ ]`: unfiled
  - `- [x]`: filed
  - `- [-]`: dropped. The Vault has the custom-state-for-task-list plugin.

What a Dump keeps: Learnings, Decisions with their Rationale, and Todos. It never holds a whole transcript.

Example:

```markdown
---
tags:
  - dump
  - AIGenerated
  - ClaudeCode
---
Session: Claude Code · `~/Projects/Brain-Dump` @ `main` · 2026-10-05 19:40 · [[Brain-Dump]]

## Learnings
- [ ] Codex removed custom prompts in 0.118; `SKILL.md` skills are the only Codex extension point.

## Decisions
- [ ] Filing is append-only in v1.
	- Why: protect curated notes from accidental overwrite.

## Todos
- [ ] #todo Decide skill packaging.
```

## 2. `dump`

Decided in [How does dump find The Vault from any repo on Linux and macOS?](https://github.com/ChrisKalahiki/Brain-Dump/issues/5) and [Which route captures a chat-app Session as a Dump?](https://github.com/ChrisKalahiki/Brain-Dump/issues/8).

### Modes

| Invocation | Source of Items | Tools |
|---|---|---|
| `dump` | The current Session's live context (whatever survives compaction). The agent writes the Items. | Claude Code, Codex |
| `dump --paste` | A Dump body the user pastes, produced in a chat app by the chat prompt. The agent adds the filename, frontmatter and origin line. | Claude Code, Codex |
| `dump <chat URL>` / "the open tab" | The chat read through Claude in Chrome. The agent writes the Items. A convenience route; long-chat completeness is unverified. | Claude Code only |

One command makes exactly one Dump. An optional free-text argument narrows the focus, for example `dump just the auth decisions`.

### Locating the Vault

1. The Vault path is `~/Documents/The Vault`, unless `~/.config/brain-dump/config` exists and sets another one. The Vault path is the only setting.
2. Refuse unless `<Vault>/.obsidian/` exists.
3. Create `<Vault>/Inbox/` if it is missing.

### Writing

- The agent writes the file with its own file-write tool. There is no helper script in v1; switch to one only if the agent gets filenames wrong.
- **On failure** (the Vault is missing or invalid, or the write is denied): stop, say why, and print the complete Dump into the Session so the user can copy it or retry. There is no fallback queue.

## 3. `file`

Decided in [How is a Filing proposal presented and approved?](https://github.com/ChrisKalahiki/Brain-Dump/issues/6) and [How does Filing choose or create its target Weekly Note and Topic Notes?](https://github.com/ChrisKalahiki/Brain-Dump/issues/7).

### Run

`file` processes every Dump in `Inbox/` (not `Inbox/Filed/`) that still has `- [ ]` Items, oldest first, one Filing Plan per Dump. `cancel` stops the run, and the remaining Dumps wait for the next one.

### Filing Plan

A numbered table, with one row per unfiled Item:

- the Item's kind and a short excerpt
- its destination note and section
- whether the destination is NEW
- how it will be appended

Below the table, the plan lists any new notes (with folder and tags) and any new tags, and states that Filing is append-only. Nothing is written until the user replies.

| Reply | Effect |
|---|---|
| `ok` | Apply the plan. |
| `skip N` | Leave Item N unfiled (`- [ ]`) for a later run. |
| `drop N` | Mark Item N dropped (`- [-]`); it will never be filed. |
| `N → [[Note]]` | Redirect Item N. Then offer the redirect back as a new Route. |
| `show N` | Print the exact text Item N would append. |
| `edit N` | Reword Item N before filing. |
| `cancel` | Write nothing and stop the run. |

Replies can be combined, for example `3 → [[Zotero Plug-in for Obsidian]], show 4`.

### Destinations

- **Todos** go to the `# To-Do:` section of the Weekly Note for the week Filing runs, as `- [ ] <text> #todo`, with no backlink.
- **Learnings** go to the best-matching Topic Note.
- **Decisions** go to a Topic Note when they're really about a general subject. Otherwise they go to the Project Note, which is also the default when it's unclear.
- **Link line:** for each filed Dump, one line goes under `# Notes:` in the Weekly Note for the week the Session happened (the Dump's date). For example: `- Filed [[<dump filename>|<project> <slug>]]`.

**Finding a week's Weekly Note:**
- Use the latest `Research/Weekly Meetings/MM-DD-YY Weekly Update.md` dated within the 7 days up to the target date.
- If there isn't one, the plan proposes creating it, as a NEW row: a verbatim copy of `Research/Other/Templates/XX-XX-XX Weekly Update.md`, named for that week's Monday.

**Finding Topic Notes and Project Notes:**
- Search note titles, folders, tags and the Dump's project.
- Consult `Inbox/Filing Routes.md` first. It is a plain, user-editable list of Routes, one per line: `<project or subject> → [[note]]`.

**New notes:**
- Content: tags-only frontmatter using existing tags, followed by the filed Items. No template.
- Folder: proposed in the plan. Project Notes go to `Side Projects/<Project>/` and research topics to `Research/Main Notes/`. The folder can be redirected.
- Tags: Filing reuses existing tags (CamelCase topics, `#todo`). A new tag only appears as a proposal in the plan.

### Appending rules

- **Append-only:** never edit or delete existing text.
- **One exception:** a completely empty placeholder bullet (`- ` or `- [ ] `) in the target section is filled instead of left behind.
- **Topic Notes and Project Notes:** the Item is added as a bullet at the end of the note. A Decision keeps its `\t- Why:` line. Both kinds get a `\t- From [[<dump filename>|dump MM-DD-YY]]` backlink.
- **Weekly Note sections:** insert at the end of the section, before its `---` separator.

### After applying

- Tick each filed Item `- [x]` in the Dump, and mark each dropped Item `- [-]`.
- Once no `- [ ]` Items remain, move the Dump to `Inbox/Filed/`, so backlinks keep resolving.

## 4. Chat prompt

Decided in [Which route captures a chat-app Session as a Dump?](https://github.com/ChrisKalahiki/Brain-Dump/issues/8).

`prompts/chat-dump.md` instructs a chat app to output only a Dump body: the §1 sections and Items, with no frontmatter and no origin line. The user pastes the prompt once into a Claude Project's instructions, or pastes it into ChatGPT or Gemini when needed. The chat's output is handed to `dump --paste`.

## 5. Packaging, install and permissions

Decided in [How can one command work in both Claude Code and Codex CLI with the Session's context?](https://github.com/ChrisKalahiki/Brain-Dump/issues/3) and [How are the Brain-Dump skills packaged, installed and granted Vault write access?](https://github.com/ChrisKalahiki/Brain-Dump/issues/9).

```text
skills/
├── dump/SKILL.md        # Claude Code + Codex
└── file/SKILL.md        # Claude Code only
prompts/
└── chat-dump.md
install.sh
```

- **Skill format:** one Agent Skills `SKILL.md` per skill. It runs inline in the conversation; never use `context: fork`. Avoid relying on `$ARGUMENTS` or `` !`cmd` ``, which Codex doesn't support.
- **`install.sh`:**
  - Symlinks `skills/dump` into `~/.agents/skills/` and `~/.claude/skills/`.
  - Symlinks `skills/file` into `~/.claude/skills/` only.
  - Edits no config: no Claude settings, no Codex config, nothing in Obsidian.
  - Prints the one-time manual steps:
    - macOS: grant the terminal app access to Documents.
    - Install Claude in Chrome if you want `dump <URL>`.
    - The location of `prompts/chat-dump.md`.
- **Install on the Mac:** clone, then run `install.sh`. Update on either machine with `git pull`.
- **Invocation:** both skills are manual-only:
  - Claude Code: `disable-model-invocation: true`
  - Codex: `agents/openai.yaml` with `policy.allow_implicit_invocation: false`
- **Write permissions:**
  - **Claude Code, `dump`:** `allowed-tools: Edit(~/Documents/The Vault/Inbox/**)`.
  - **Claude Code, `file`:** `allowed-tools: Edit(~/Documents/The Vault/**)`. The approved Filing Plan is the safeguard.
  - **Codex, `dump`:** nothing configured. Codex prompts once for each Dump.

## Verify during the build

- [ ] `allowed-tools` accepts a path containing a space (`The Vault`).
  - If it doesn't, the fallback is a global allow rule for `Inbox/**` only in `~/.claude/settings.json`, which the user adds themselves.
  - Under that fallback, `file` accepts a prompt for each write.
- [ ] `dump <chat URL>` reads a long claude.ai chat in full through Claude in Chrome.
  - If it doesn't, document `--paste` as the route for long chats.
- [ ] A Codex `dump` write outside the workspace triggers an approval prompt, rather than failing under the default sandbox.

## Proposed build slices

1. `dump`, Session mode: locating and validating the Vault, the Dump format, filenames, and the failure print.
2. `install.sh` and manual-only invocation in both tools, plus the `allowed-tools` check.
3. `dump --paste`, plus `prompts/chat-dump.md`.
4. `dump <chat URL>` through Claude in Chrome.
5. `file`, the Filing Plan: discovering Dumps, choosing destinations, Routes, and handling replies.
6. `file`, applying a plan: the append rules, creating Weekly Notes and new notes, ticking Items, and moving finished Dumps to `Inbox/Filed/`.
